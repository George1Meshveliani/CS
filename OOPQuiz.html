Theoretical Questions 1 – 3
Q1 The Four Pillars of OOP Theory

OOP is built on four fundamental principles. For each one:

  • State its name and give a one-sentence definition in your own words.
  • Explain how it helps a developer write better, more maintainable code.
  • Give a concrete real-world analogy (not the same as any example in the notes).

Additionally, explain why these four pillars are complementary — how does each one rely on or enable the others?

Think about what problems arise in large codebases when these principles are absent. What breaks first when there is no encapsulation? What becomes impossible without polymorphism?
Q2 Virtual Functions & Polymorphism Theory

Consider the following C++ declarations:

class Base { public: void regularMethod(); virtual void virtualMethod(); virtual void pureVirtual() = 0; };

Answer the following:

  • What is a vtable and how does C++ use it at runtime to dispatch a virtual method call?
  • What is the difference between compile-time (static) polymorphism and runtime (dynamic) polymorphism? Give one example of each.
  • Why does a class that declares at least one pure virtual function become abstract? What does this prevent, and why is that useful?
  • What happens if a derived class does not override a pure virtual method?
Remember: virtual instructs the compiler to resolve the call through a pointer table rather than at compile time. Think about what "object slicing" means and when it can silently break polymorphism.
Q3 Diamond Problem & Virtual Inheritance Theory

Multiple inheritance can lead to the infamous diamond problem.

// Diamond hierarchy class A { public: int x = 1; }; class B : public A {}; class C : public A {}; class D : public B, public C {};

Answer the following:

  • Describe exactly what ambiguity occurs when you write D d; d.x; without virtual inheritance.
  • How does adding virtual to the inheritance of B and C resolve this? What guarantee does the compiler now give?
  • Languages like Java and C# do not support multiple class inheritance. What mechanism do they provide instead, and what problem does that design avoid?
  • Is there a scenario where the diamond problem is actually desirable (i.e., you intentionally want two separate copies)? Justify your answer.
Draw the inheritance graph as a diamond shape. Without virtual, D contains two separate A sub-objects — one via B, one via C. With virtual, only one shared A sub-object exists.
Practical Questions 4 – 5
Q4 Design a Class Hierarchy Practical

Design and implement a small C++ class hierarchy for a zoo management system. Your solution must demonstrate all four OOP pillars.

Requirements:

  • Create an abstract base class Animal with:
    • Protected data: name (string), age (int).
    • A pure virtual method speak() that prints the animal's sound.
    • A virtual method describe() that prints name and age (derived classes may override it).
    • A public getter for name (encapsulation).
  • Create at least two concrete derived classes (e.g., Dog, Bird) that override speak() and add at least one unique data member each.
  • Create a Zoo class that holds a std::vector<Animal*> and provides:
    • addAnimal(Animal* a)
    • allSpeak() — calls speak() on every animal (demonstrating runtime polymorphism).
  • In main(), construct a Zoo, add animals of different types, call allSpeak(), and print each animal's name via the getter.

Bonus: Add a destructor to Animal and explain why it must be virtual.

Start by writing the abstract class first — the compiler will tell you if you forgot to override a pure virtual. Use = 0 syntax for pure virtuals. Remember to declare virtual ~Animal() {} so delete animal_ptr calls the right destructor.
Q5 Fix the Broken Code Practical

The following C++ program contains four distinct OOP-related bugs. Find every bug, explain what is wrong, and write the corrected version of the code.

#include <iostream> #include <string> using namespace std; class Shape { public: double area; // Bug A virtual double getArea() = 0; ~Shape() { cout << "Shape destroyed\n"; } // Bug B }; class Circle : public Shape { private: double radius; public: Circle(double r) : radius(r) {} double getArea() { return 3.14 * radius * radius; } }; class Rectangle : public Shape { private: double width, height; public: Rectangle(double w, double h) : width(w), height(h) {} double getArea() { return width * height; } }; void printArea(Shape s) { // Bug C cout << "Area: " << s.getArea() << "\n"; } int main() { Circle c(5.0); Rectangle r(4.0, 6.0); Shape* shapes[] = { &c, &r }; for (auto* s : shapes) printArea(*s); // Bug D (consequence of Bug C) return 0; }

For each bug (A – D):

  • Identify the exact line / construct that is wrong.
  • Explain the OOP or C++ principle being violated.
  • Write the corrected code for that section.
Bugs to think about: exposing raw data members breaks encapsulation; forgetting virtual on a destructor causes resource leaks when deleting through a base pointer; passing a base-class object by value loses the derived type — this is called "object slicing"; and abstract classes cannot be instantiated directly.
